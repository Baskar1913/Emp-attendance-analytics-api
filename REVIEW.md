# REVIEW.md — Review of the Supplied Starter

## Scope and method

The supplied `candidate_kit/app/main.py` was reviewed against `openapi.yaml`, `DATA_MODEL.md`, and business rules R1–R10. The review covers correctness, validation, time-zone handling, concurrency, database behavior, analytics, and performance at approximately 100,000 attendance records.

The starter's happy path was not treated as proof of correctness. Each finding below describes the starter defect, a scenario that exposes it, and the corrective behavior required in the current implementation. These scenarios are test cases; they should not be described as passing until actually executed against MongoDB.

## Defects found

| # | Starter location | Defect and impact | How to reveal it | Correction / expected behavior |
|---:|---|---|---|---|
| 1 | `compute_late_minutes` | The helper replaces the punch timestamp's clock fields with the shift start but retains a naive datetime. This is unsafe for time zones and overnight shifts. | Use a 22:00–06:00 employee with a punch-in at 02:00 IST; that punch belongs to the previous shift-start date. | Normalize instants to UTC-aware datetimes, derive the attendance day in IST, and compare against shift start anchored to that day. |
| 2 | Timestamp helpers / request models | The starter does not enforce integer epoch milliseconds or truncate instants to whole seconds before calculation and persistence. Seconds, floats, strings, or sub-second values can lead to invalid or inconsistent behavior. | Send `punched_at` as a string, float, seconds-looking value, or a millisecond value with sub-second precision. | Validate strict integer milliseconds, reject invalid types/ranges with `422`, truncate to whole seconds, and store/return the truncated instant. |
| 3 | `compute_work_hours` | Python's built-in `round` uses ties-to-even behavior for halfway values, while the contract requires decimal half-up rounding. | Use a duration that produces an exact halfway value at the second decimal place. | Use `Decimal` with `ROUND_HALF_UP` and apply the same rounding rule to reported numeric values. |
| 4 | `compute_overtime` | The starter anchors shift end to the attendance date unconditionally and mixes naive punch-out values with an IST-aware shift-end value. Overnight shifts can be calculated incorrectly or raise a datetime comparison error. | Punch out at 06:40 IST after a 22:00–06:00 shift that began the previous day. | Place the shift end on the next calendar day when `shift_end <= shift_start`; compare normalized instants and count overtime only when it reaches 30 minutes. |
| 5 | `GET /health` | The starter returns `200` without proving MongoDB is reachable. A running web process can appear ready while its database is unavailable. | Stop MongoDB and call `/health`. | Ping MongoDB and return `200` only on a successful ping; return `503` when the database cannot be reached. |
| 6 | `POST /employees` and indexes | A read-before-insert duplicate check is not atomic. Two simultaneous requests can both pass the check if there is no unique database index. | Send concurrent creates with the same `emp_code`. | Create a unique index on `employees.emp_code` at startup and translate `DuplicateKeyError` to `409 Conflict`. |
| 7 | `EmployeeIn` / `POST /employees` | The starter model does not fully validate employee code, email, date, shift-time format, or unequal shift boundaries. Invalid input can reach persistence. | Submit malformed `emp_code`, invalid email/date/time, or identical shift start/end values. | Use Pydantic constraints and explicit date validation; reject invalid bodies with `422`. |
| 8 | `POST /employees` | `created_at` is written with naive `datetime.now()`, making the stored instant dependent on the host's local time zone and inconsistent with the UTC-instant convention. | Run on a host configured outside UTC and inspect the stored creation instant. | Store a UTC-aware timestamp, truncate it to whole seconds, and serialize API instants as epoch milliseconds. |
| 9 | `GET /employees` | The starter uses `page * page_size` as the skip offset, so page 1 skips the first page. Its `total` ignores the department filter, and results are not sorted by `emp_code`. | Create several employees; request page 1 and filter to a department containing fewer employees than the full collection. | Use `(page - 1) * page_size`, count the same filtered query, sort by `emp_code` ascending, and enforce R10 pagination bounds. |
| 10 | `POST /attendance/punch-in` | The starter does not return a clean `404` for an unknown employee before accessing shift fields. It uses local-time conversion and truthiness for `punched_at`, mishandling epoch values and potentially assigning the wrong IST attendance date. | Punch in for a nonexistent employee; send `punched_at=0`; test an overnight-shift punch before shift-end time. | Validate the employee and timestamp, distinguish omitted values from invalid supplied values, normalize to UTC, and derive the IST attendance date according to R1. |
| 11 | `POST /attendance/punch-in` and attendance uniqueness | A check-then-insert query alone cannot guarantee one record per employee/date. The starter also does not restrict punch-in statuses to the three presence statuses. | Fire parallel punch-ins for the same employee/date; submit `ABSENT` or `LEAVE` to punch-in. | Enforce a unique compound index on `(emp_code, date)`, map duplicate-key races to `409`, and accept only `PRESENT`, `WFH`, or `ON_DUTY` for punch-in. |
| 12 | `GET /attendance` | The starter fetches all matching documents into Python and sorts/slices in memory. It does not fully validate date/status/page inputs and can expose raw BSON datetime fields or an internal/synthetic identifier contrary to the contract. | Use a large result set; test `date_from > date_to`, invalid status, and page bounds; inspect response types and fields. | Filter, sort, skip, and limit in MongoDB; validate query parameters; count the filtered set; serialize instants as epoch milliseconds and omit MongoDB `_id`. |
| 13 | Missing `POST /attendance/punch-out` | The starter has no punch-out route, so it cannot close a record or enforce the one-winner rule for concurrent punch-outs. | Call the contract route; then send simultaneous punch-out requests for the same open record. | Implement an atomic update that only matches an open record and compute work hours, overtime, and half-day status from the final timestamps. Exactly one concurrent request should update successfully. |
| 14 | Missing `PATCH /attendance/{emp_code}/{date}` | There is no regularization endpoint, so the starter cannot validate corrected values or preserve audit history. | Correct punch-in/status/punch-out; repeat with a no-op request and with concurrent corrections. | Validate allowed combinations, recompute derived fields, record only actual changes in `history[].changes`, append rather than replace history, and handle concurrent edits without silently losing entries. |
| 15 | Missing analytics routes | Employee monthly summary, department summary, late leaderboard, and department trend are absent from the starter. | Call each analytics path in the OpenAPI contract. | Implement all four reports with MongoDB aggregation pipelines rather than fetching records and calculating reports in Python. |
| 16 | Analytics semantics | The contract includes non-obvious cases: headcount includes eligible employees without logs, present-day counts exclude weekends and weight half days, average hours is record-weighted, leaderboard ties use competition ranks, and trend output fills calendar gaps. | Create fixtures for no-log employees, mid-month joiners, weekends, half days, ties, and missing trend dates. | Express the calculations in aggregation stages and follow R5–R9, including competition ranking and a seven-row moving average within the requested date range. |
| 17 | Missing explain route and supporting indexes | The starter does not provide the explain endpoint or supporting indexes required for predictable behavior at the target data volume. | Call each explain target and inspect `executionStats` against a realistically sized database. | Create indexes idempotently at startup and expose execution statistics for the same query/pipeline used by the named endpoint. Check for `IXSCAN` and investigate any `COLLSCAN`; index definitions alone do not prove a good plan. |
| 18 | Cross-cutting validation and errors | The starter does not consistently distinguish missing resources, conflicts, and invalid requests. Unhandled errors can produce `500`, which the assignment treats as a failed test. | Test unknown employees/records, invalid timestamps, duplicate requests, and malformed dates. | Return `404` for missing resources, `409` for conflicts, `422` for validation errors, and handle database failures deliberately. |

## Areas reviewed and retained

- **Employee identity:** `emp_code` is the business identifier. MongoDB `_id` remains internal and is not accepted or returned as the API identity.
- **Collection names:** `employees` and `attendance_logs` match the supplied data model and are retained.
- **Manual history semantics:** `history` is reserved for successful manual corrections. Punch-in and punch-out must not append correction entries.
- **Stored derived values:** analytics read stored `work_hours`, `late_minutes`, `overtime_minutes`, and `half_day`. They must not recompute historical values from timestamps because seeded values are authoritative.
- **No-record versus absent:** a missing attendance document is not equivalent to an `ABSENT` document. Trend and headcount calculations must preserve this distinction.
- **Contract over assumptions:** the OpenAPI contract and R1–R10 take precedence over assumptions based only on the small sample dataset.

## Verification note

This review documents defects identified in the supplied starter and the corrective design intended in the current implementation. It is not a substitute for running the full contract suite. Before submission, exercise the boundary and concurrency cases above against MongoDB, inspect all five explain targets, and record any remaining known limitation honestly.
